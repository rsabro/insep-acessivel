01

Visão geral do Front-End

O Front-End do INSEP Acessível é responsável pela camada visual e interativa do sistema.

A equipe transforma os requisitos e protótipos em páginas funcionais, responsivas e acessíveis.

O Front-End coleta e valida informações, apresenta respostas ao usuário e se comunica com o Back-End por meio de APIs.

04

Acessibilidade como requisito

A acessibilidade faz parte da definição da interface, implementação e testes.

  • HTML semântico e estrutura lógica de títulos.
  • Navegação completa por teclado.
  • Foco visível em links, botões e campos.
  • Textos alternativos adequados para imagens.
  • Labels associados corretamente aos campos.
  • Mensagens de erro claras e perceptíveis.
  • Contraste adequado entre texto e fundo.
  • Compatibilidade com zoom e diferentes telas.
  • Modo claro e escuro.
  • Recursos de acessibilidade e Libras.

07

Organização com Git e GitHub

O Git mantém o histórico das alterações e permite que a equipe trabalhe em paralelo.

main → homolog → develop → feature/*
  • feature/*: desenvolvimento de uma funcionalidade.
  • develop: integração das funcionalidades.
  • homolog: validação antes da publicação.
  • main: versão estável/publicada.

Exemplos:

feature/login feature/cadastro feature/home feature/perfil feature/acessibilidade
08

Pull Request e revisão

  1. Criar uma branch para a funcionalidade.
  2. Desenvolver e testar localmente.
  3. Fazer commits objetivos.
  4. Enviar a branch para o GitHub.
  5. Abrir Pull Request para develop.
  6. Outro integrante revisa o código.
  7. Corrigir problemas apontados.
  8. Realizar o merge após aprovação.
  9. Testar a integração.
  10. Publicar em main após validação.
09

Padrão de commits

feat: adiciona validação no cadastro fix: corrige mensagem de erro do login style: ajusta responsividade da home docs: atualiza documentação

11

Validação de formulários

  • Campo obrigatório vazio.
  • E-mail inválido.
  • Credenciais incorretas.
  • Cadastro duplicado.
  • Mensagens acessíveis para tecnologias assistivas.
12

Testes do Front-End

  • Navegação com teclado.
  • Foco e ordem de navegação.
  • Formulários e mensagens de erro.
  • Celular, tablet e desktop.
  • Zoom e redimensionamento.
  • Links, botões, menus e modais.
  • Imagens e textos alternativos.
  • Contraste e legibilidade.

13

Critérios de aceite

  • A página abre sem erros.
  • Elementos utilizáveis por teclado.
  • Formulários apresentam validações claras.
  • Botões e links possuem nomes compreensíveis.
  • Layout adaptável a diferentes telas.
  • Alterações passam por revisão.
  • Funcionalidade testada antes da publicação.

16

Conclusão

A estratégia da equipe Front-End é transformar os requisitos do projeto em uma experiência web acessível, organizada e testável.

O foco está na interface, experiência do usuário, acessibilidade, validação, integração com APIs e qualidade da entrega.

Nosso foco como equipe Front-end não é apenas fazer a página funcionar. É fazer com que o usuário consiga realmente utilizar o sistema, inclusive pessoas que dependem de recursos de acessibilidade.
